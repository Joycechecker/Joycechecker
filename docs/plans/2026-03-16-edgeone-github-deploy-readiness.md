# GitHub + EdgeOne 部署整理说明

## 目标

把当前项目整理成适合直接上传到 GitHub，并在 EdgeOne Pages 上部署的状态，同时避免把本地开发残留、密钥和导出产物一起推上去。

## 本次整理内容

1. 补充仓库忽略规则
   - 忽略 `src.zip`
   - 忽略本地导出的战略会议报告 HTML
   - 忽略 `.edgeone`、`.vercel` 和日志文件
   - 继续忽略所有 `.env*`，但保留 `.env.example`

2. 明确运行时要求
   - 在 `package.json` 中补充 `Node >=20.9.0 <23`
   - 便于部署平台识别兼容的 Node 版本

3. 补充部署说明
   - 在 README 中加入 GitHub 与 EdgeOne 的推荐部署步骤
   - 明确需要配置的环境变量，尤其是 AI Key 和登录保护

## 为什么这样整理

当前仓库是在真实迭代过程中形成的，目录里带有：

- AppleDouble 文件
- 本地压缩包
- 导出的 HTML 报告

这些东西对 GitHub 和线上部署都没有帮助，反而容易造成：

- `git add .` 时把无关文件一起推上去
- 同事误以为这些产物是应用的一部分
- 线上仓库出现不必要的噪音

## 部署建议

部署时优先使用 EdgeOne Pages，并在平台环境变量中配置：

- 豆包 / 方舟相关变量
- 登录保护相关变量

本地 `.env.local` 不应上传到 GitHub；线上环境变量应在平台控制台单独维护。
