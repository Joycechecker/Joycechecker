# 私有登录保护设计

## 背景

当前 Studio 已经接了真实 AI 文案和图片接口。如果直接把站点部署到公网，而没有登录保护，陌生人可以直接访问工作台并消耗服务端 token，风险包括：

- 未授权调用导致 API 费用失控
- 陌生人占用生成额度与性能
- 后续做收费前，产品入口没有最基本的访问控制

## 目标

先落一版适合当前阶段的“私有邀请制登录”：

- 只有环境变量里预设的账号可以登录
- `/studio` 必须登录后可访问
- 选题分析、成稿生成、图片生成、优化稿件这些 API 也必须登录后可调用
- 不引入第三方重型鉴权依赖，便于先部署验证

## 方案

采用邮箱/密码登录 + HttpOnly 会话 Cookie。

- 登录页提交邮箱和密码到 `/api/auth/login`
- 服务端校验环境变量中的允许账号
- 登录成功后写入签名会话 Cookie
- `middleware.ts` 保护 `/studio` 和 AI API
- 服务器组件 `studio/page.tsx` 再做一层校验，避免单点失效
- 退出登录通过 `/api/auth/logout` 清掉 Cookie

## 配置方式

支持两种环境变量模式：

1. 单账号：
   - `AUTH_SECRET`
   - `AUTH_LOGIN_EMAIL`
   - `AUTH_LOGIN_PASSWORD`
   - `AUTH_LOGIN_NAME`

2. 多账号：
   - `AUTH_SECRET`
   - `AUTH_USERS_JSON`

## 边界

这版目标是先挡住陌生人，不是完整的商业化账号系统。它不包含：

- 用户注册
- 找回密码
- 邮箱验证码
- 套餐、Credits、订单同步

后续如果要对外收费，可在这套会话保护之上继续接正式账户系统和支付逻辑。
